# 1.10.2 pre-release

This pre-release adds opt-in BC Data tools for development containers and bundles the companion AL app in the extension. CI builds the companion from the release's source; no checked-in compiled app is used.

## BC Data

- Discover configured connections and companies, check readiness, find tables, inspect schemas, and read bounded pages of records through six `bc_dev_toolset_data_*` MCP tools.
- Use `bc_dev_toolset_data_mutate_records` for an explicit insert, modify, rename, or delete of one record. Native permissions, security filters, validation, and triggers apply. Row versions protect updates; transactional receipts support one identical transport retry within the same call.
- Enable tools explicitly, configure a development connection, and run **Initialize BC Data Access** to install the bundled companion. Mutation operations require an explicit per-connection allowlist, write access, and native business-table permissions. All data tools and mutation operations are disabled by default.
- Store UserPassword credentials in Windows Credential Manager. The client uses the qualified HTTP/1.0 transport to avoid the reproduced large-response failure in the BC27.1 server's default chunked-response path.
- Validate the bundled app, checksum, compatibility metadata, and final VSIX contents before distribution. Explicit initialization is idempotent and does not downgrade an installed companion.

See [BC Data setup](../../vscode-extension/README.md#bc-data-access) and the [compatibility evidence](../BCDataCompatibilityExperiments.md).

## Development and test tooling

- Select test containers by their configured application platform and the app's baseline. Development suites use the baseline; compatibility suites exercise newer targets. Automated suites require Test-role containers.
- Replace `executeTestsInContainerName` with platform-based test selection and migrate legacy settings. Add compatibility operations for AL, page scripts, and AL Runner.
- Build before preparing and deploying test targets, report actual application/platform versions, and route launch targets by Dev/Test role.
- Preserve database source identity, dotted database names, and file mappings during backup/restore, and recover SQL before checking a stopped BC service. The separately documented BC27 restore administration dependency issue remains unresolved.
- Allow non-sensitive MCP decisions to be answered through chat while keeping sensitive prompts in the user terminal. Isolate Extension Development Host user data.

## Qualification and limits

The selected W1 BC23, BC24, BC25, BC26, and BC27.1 builds passed the AL, public-service authorization, concurrency/receipt, Node client, and MCP mutation checks. BC25 was exercised with both tri-state and legacy locking. Hosted CI also passed the clean companion build and final VSIX validation; a fresh BC23 installation verified explicit initialization and subsequent reads.

This qualification covers OnPrem development containers with UserPassword authentication, not SaaS or general remote production environments. It does not certify every cumulative update, BC27.0, or live HTTPS. FlowField writes are rejected. Rename qualification covers the documented three-part GUID/Code/Integer fixture. Retry receipts do not guarantee replay safety across database restore/copy or external side effects. Backup/restore is not required for ordinary BC Data use.
